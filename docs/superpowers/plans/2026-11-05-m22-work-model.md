# Milestone 22: the work model

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal.** Tasks and Projects become work items. Any work item can carry ticket fields; every work item has work fields, an ordered step list with a current step and a whose-turn, list and floor-item fields, an `## Activity` log and `## Work notes` that every work write appends to, and a resolution note with Copy buttons. "Done" is Object's own status. A built-in **Tickets** view lists every work item with a Ticket ID. "Add work fields" puts the fields on another type. No agent runs in this milestone; agents get the matching tools.

**Architecture.** Pure rules (`workrules.py`, ported 1:1 to `frontend/src/work/stepRules.ts` with a shared parity fixture) decide the current step, whose turn, the stage and every allowed move. Three new property kinds (`steps`, `textList`, `floorItems`) are YAML lists in front matter, read and written by `workvalues.py` through the M2 codec, so an edit rewrites only that property's lines. `workfields.py` defines the fields and tops up the basic Task type in memory (as M4 does for the Task fields). Every work write goes through **one** service (`workservice.py`) and one new `Space.write_work` call, which changes the property lines and appends the Activity (and Work notes) lines in **one** atomic, version-checked, stamped write. Step actions are checked per step (id + revision): a stale step answers 409 "This step changed. Look again." The app routes (`api_work.py`), the agent routes (`api_v1_work.py`) and the `objectapp-mcp` tools all call that service. M23 (the Work section) and M24 (brain dump and the agent loop) consume this Contract.

**Tech Stack.** Python 3 (FastAPI, pydantic, ruamel.yaml through `frontmatter.py`), `uv`; React, TypeScript, zustand, shadcn/ui, Tailwind, vitest. No new dependencies. No CLI flags are used by this milestone (no agent runs), so none are named.

**Spec.** `docs/superpowers/specs/2026-11-05-work-dashboard-design.md`, sections **1** (work items and ticket fields, the Tickets view, Done, Stage, On Hold), **2** (work fields, the Project relation on Tasks), **3** (steps: kinds, states, rules, storage), **4** (Activity, Work notes, the resolution note), and "Add work fields" from the Our calls list. Sections 5-8 are M23's and M24's; this plan only provides what they consume. The rules being ported were read (read-only) from `C:\Git\ticket-dashboard\docs\DASHBOARD-SECTION.md`, `actions.py` and `resolution.py`; the wiki was not read.

## Global Constraints

- Never write on read: listing work items, reading one, topping up Task with work fields, serving the Tickets view and inferring System for display write no file (`.md`, type, query, state).
- A property edit changes only its own lines. A work write changes only: the edited property's lines, the `lastUpdated` stamp (and an `id` inserted first when missing), the System line when inferred, the `completed` line on a done/reopen crossing, and the appended `## Activity` / `## Work notes` lines (plus their heading when the section is new).
- CRLF and BOM are kept; every write is atomic (`Space._write`); a write that changes nothing writes nothing.
- Deletes go to the Trash. Removing a step, a list item or a floor item is an edit of that property, kept in version history (M8), not a delete.
- Fixtures are synthetic (`INC0012345`, `OPS-123`, "Printer jams on line 3"); no real ticket, host or person.
- Every feature unlocked; no upsell, badge or limit beyond the caps named here.
- The server binds 127.0.0.1 only. No network at runtime (the Jira link is text, never fetched).
- Done is Object's own status: Task Done / Project Completed. The Desk status never changes Object's status.
- Done items stay visible for **14 days** from the status change (`DONE_VISIBLE_DAYS = 14`), then only in Everything (M23).
- Stage: Task Not Started / Project Planned = **Not started**; Task Next Up = **Ready**; Task In Progress / Project In Progress = **Doing**; Task On Hold / Project On Hold = **Waiting / parked**; Done / Completed = **Done**.
- Whose turn: Question/Do → **you**; Approve (Open) → **approve**; Approve (Approved) or Agent → **agent**; On Hold → **parked**; every step done while active, or the desk says Resolved/Closed → **close**; no steps → **none**.
- The current step is the first step that is neither Done nor Declined. No action is accepted on a step after the current one.
- Moves: Question and Do: Open → Done. Approve: Open → Approved → Done (only the agent marks it done), Open or Approved → Declined; Approved can be withdrawn to Open; a Done Approve step never reopens. Agent: Open → Approved (queued) → Done, or Open → Done.
- A stale step action answers HTTP 409 with exactly `This step changed. Look again.`
- Activity line: `- YYYY-MM-DD HH:MM <who> <what>` (space time zone), append-only on disk, newest first in the UI. Work notes line: `- [YYYY-MM-DD] <who>: <verb> step n "<step>": <text>`.
- System is set from the id's shape when empty: `ABC-123` = Jira, anything else = ServiceNow; editable. Desk priority "Moderate" reads as Medium.
- Agents run only through the `claude` CLI under Gene's login (M17); this milestone starts none. Object never reads `~/.claude/.credentials.json` or any Claude token and never calls Anthropic's API. Tests use `OBJECT_STATE_DIR` in a temp folder and never touch `~/.claude`.
- Never name the original notes app or the open-source agent whose patterns the agents design adopts, in code, strings, fixtures or docs.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

The five failure modes no task's ordinary tests would catch, most likely first. Each has its test in the owning task.

1. **A work write touches more than it should.** Re-rendering other keys, a blank line slipped between Activity items, `## Wrap-up` moved, CRLF or BOM lost, two writes for one action (a property write then a body save). Test: `backend/tests/test_m22_writes.py::test_step_action_diff_is_steps_stamp_and_two_body_lines` (T7), on the CRLF+BOM fixture, comparing bytes outside the expected hunks.
2. **The approval gate can be bypassed.** An agent approves, declines, withdraws or reopens; Gene marks an Approve step done; the text of an approved step is edited (so what runs isn't what was approved); `steps` is written by `PUT /api/object/properties`, `/api/v1/object/properties`, an automation's `setProperty`, or created with a non-open state through `POST /api/objects`. Test: `backend/tests/test_m22_writes.py::test_gate_cannot_be_bypassed` (T7, parametrised over every path) and `test_m22_values.py::test_generic_paths_refuse_steps` (T3).
3. **A hand-edited step list loses data on the next write.** An entry with an unknown kind, a non-mapping entry, unknown keys inside a step, steps without ids, duplicate ids. Test: `backend/tests/test_m22_values.py::test_unreadable_list_refuses_writes_and_keeps_bytes` and `::test_unknown_step_keys_survive_a_write` (T3).
4. **Two actions on one step both land.** A double press of Approve, two windows, Gene and an agent at once. The second must be 409 with the exact text and write nothing; an action on a different step still lands. Test: `backend/tests/test_m22_api.py::test_second_action_on_the_same_step_is_409` (T8, two threads against one space).
5. **Reads write.** Opening a space whose Task type gains work fields in memory, listing work items, reading the Tickets view, a Project type without work fields. Test: `backend/tests/test_m22_api.py::test_reads_write_nothing` (T8: `git status` of the space copy and the state dir file list are unchanged after every read route).

**On disk** (block style; `frontmatter._rt_yaml` writes sequences indented 2 under the key):

```yaml
steps:
  - id: q4m2xa
    kind: question
    state: done
    text: Which tray jams most often?
    answer: Tray 2, mostly in the morning
    addedAt: 2026-11-04T14:02:00.000Z
    doneAt: 2026-11-04T15:10:00.000Z
  - id: r8k1pd
    kind: approve
    state: open
    text: Restart the print spooler on PRN-TEST-01
verified:
  - The spooler log shows 3 crashes on 2026-11-03
floorItems:
  - id: f3k9wz
    place: Line 3 printer
    what: Photo of the error panel
    collected: 2026-11-05
    found: Code E-12 on the panel
```

- **Step mapping keys**, written in this order, only when set: `id`, `kind` (`question` | `do` | `approve` | `agent`), `state` (`open` | `approved` | `done` | `declined`), `text`, `notBefore` (ISO UTC instant, Approve only), `answer` (Question), `result` (what the agent reported, or why it couldn't), `addedAt`, `approvedAt`, `doneAt`, `declinedAt` (ISO UTC `YYYY-MM-DDTHH:MM:SS.sssZ`). Unknown keys are kept after these, in their order. Multi-line `answer`/`result` are written as literal blocks (`|-`) when `_literal_safe`, else quoted.
- **Read leniently**: kind and state case-insensitive; a missing state is `open`; a scalar list item is read as a Do step with that text. An entry is **unreadable** when it isn't a mapping or a scalar, its kind or state is unknown, or its text is empty. A list with an unreadable entry is served with the readable steps and `problems`; every write to it is refused (422 `"The step list can't be read: fix it in the file first."`), so no entry is ever lost.
- **Ids**: 6 characters `[a-z0-9]` from `secrets`, unique in the list. On disk an id that doesn't match `^[a-z0-9]{4,12}$`, or repeats an earlier one, counts as missing. A step without an id is served as `@<n>` (its 1-based position) and gets a real id on the next write to the list. Reading never assigns one.
- **Revision**: `rev` = the first 12 hex characters of sha256 of the step's canonical JSON (its stored mapping as read, keys sorted, plus `"@n"` position for an id-less step).
- **Caps** (our choice): 50 steps, 50 floor items, 50 list items; step text 1-500 characters on one line (`"A step is one line."`); answers, results and notes up to 8000 characters (the old dashboard's cap); a list item 1-500 characters, one line.
- **textList**: a list of non-empty one-line strings (a scalar reads as a one-item list). Duplicates allowed.
- **floorItems mapping keys**: `id`, `place`, `what`, `collected` (`YYYY-MM-DD` or absent), `found`, then unknown keys. `place` or `what` must be set. Ids and revisions as steps.

### Generic paths and the gate

- `propvalues.decode_value` delegates the three kinds to `workvalues` (API forms below). `encode_value` encodes `textList` and `floorItems`, and encodes `steps` **only when every step is `open`** (else 422 `"New steps start open."`), so a create can carry open steps.
- `propvalues.GATED_KINDS = frozenset({"steps"})`: refused by `Space.update_properties` (so `PUT /api/object/properties`, `/api/v1/object/properties`, the panel and imports through it) with 422 `"Steps change with the step actions."`, and by automations' `setProperty`/`clearProperty` (as their read-only kinds).
- Merging objects never merges `steps` (the target keeps its own; the source's are listed in `dropped`). Duplicates and templates copy the front matter as they do today.

### Pure rules (`backend/objectapp/workrules.py`; TS port `frontend/src/work/stepRules.ts`)

```python
DONE_VISIBLE_DAYS = 14

def stage_of(status: str | None, status_def: PropertyDefinition | None) -> Stage

def whose_turn(stage: Stage, steps: Sequence[Step], desk_status: str | None) -> Turn
def desk_says(stage: Stage, desk_status: str | None) -> Literal["Resolved", "Closed"] | None
def recently_done(done_at: datetime | None, last_updated: datetime | None, now: datetime) -> bool
def infer_system(ticket_id: str | None) -> Literal["Jira", "ServiceNow"] | None
def normalize_desk_priority(text: str | None) -> str | None
def ticket_url(system: str | None, ticket_id: str | None, link: str | None, jira_site: str | None) -> str | None
def allowed_actions(steps: Sequence[Step], index: int, role: WorkRole) -> list[StepAction]

                 now: datetime, text: str | None = None, not_before: str | None = None,
                 ask: str | None = None, new_id: Callable[[set[str]], str]) -> list[Step]
def apply_op(steps: Sequence[Step], op: StepOp, role: WorkRole, *, now: datetime,
             new_id: Callable[[set[str]], str]) -> list[Step]

```

TS: `currentIndex(steps)`, `stageOf(status, statusDef)`, `whoseTurn(stage, steps, deskStatus)`, `deskSays(stage, deskStatus)`, `recentlyDone(doneAt, lastUpdated, now)`, `inferSystem(id)`, `normalizeDeskPriority(text)`, `ticketUrl(…)`, `allowedActions(steps, i, role)`, `applyAction(…)` (for optimistic UI; the server decides), `DONE_VISIBLE_DAYS`.

- **Stage** by the status option's text, casefolded: `not started`, `planned` → `notStarted`; `next up` → `ready`; `in progress` → `doing`; `on hold` → `parked`; `done`, `completed` → `done`; any other text by its status category (`not-started` → `notStarted`, `in-progress` → `doing`, `blocked` → `parked`, `done` → `done`); no status → `notStarted`.
- **whose_turn**, in this order: `done` stage → `none`; Desk status Resolved or Closed → `close`; `parked` → `parked`; no readable steps → `none`; no current step → `close`; current Question or Do → `you`; Approve open → `approve`; Approve approved → `agent`; Agent → `agent`. (Our call: a desk resolution beats On Hold, so a parked ticket the desk closed still surfaces for Close.)
- **desk_says**: Resolved/Closed when the stage isn't `done`, else None. The Desk status never changes `status`.
- **recently_done**: `now - (done_at or last_updated) < 14 days`; both missing → False.
- **infer_system**: stripped id matching `^[A-Za-z][A-Za-z0-9_]*-\d+$` → Jira; any other non-empty id → ServiceNow; empty → None.
- **normalize_desk_priority**: casefold `moderate` → `Medium`; the four options by casefold; anything else unchanged.
- **ticket_url**: `link` when set; else for Jira with a Jira site `"{site without trailing /}/browse/{id}"`; else None.
- **Actions** (role, from → to). An action not in `allowed_actions` raises `IllegalMove` with one message, checked in this order: the role may never take this action (on any kind) → the role message; not the current step; wrong kind; wrong state (a done Approve `reopen` has its own message); missing text; `notBefore` on another kind. Forward actions (`answer`, `done`, `approve`, `decline`, `run`, `complete`, `fail`) only on the current step.

| Action | Kinds | From → to | Who | Sets | Needs |
|---|---|---|---|---|---|
| `answer` | Question | open → done | user | `answer`, `doneAt` | text |
| `done` | Do | open → done | user | `doneAt` | |
| `done` | Agent | open, approved → done | user, agent | `doneAt` (+ `result` = text when given) | |
| `approve` | Approve | open → approved | user | `approvedAt`, `notBefore` | |
| `decline` | Approve | open, approved → declined | user | `declinedAt` | (text optional: the reason) |
| `run` | Agent | open → approved | user, app | `approvedAt` | |
| `reopen` | all | approved, declined, done → open (never a done Approve step) | user | clears `approvedAt`, `doneAt`, `declinedAt`, `notBefore`; keeps `answer` and `result` | |
| `complete` | Approve | approved → done | agent | `result`, `doneAt` | text (the result) |
| `complete` | Agent | open, approved → done | agent | `result`, `doneAt` | text |
| `fail` | Approve, Agent | approved → open | agent | `result` = text, clears `approvedAt` and `notBefore`; with `ask`, a new open Question step (text = ask) is inserted before it | text |

  `reopen` from approved is the spec's "withdraw" (the UI says Withdraw). `app` is Object itself (M24's auto-run); it may only `run`.
  Messages (our strings): `"Finish the steps before this one first."` (not current), `"This doesn't apply to a {Kind} step."` (wrong kind), `"This step is already {state}."` (wrong state, lower-case label), `"A done Approve step never reopens."`, `"Only you can do this to a step."` (an agent, or Object itself, tried an action that isn't theirs), `"Only the agent reports a step's result."` (the user tried `complete` or `fail`: the role message for users), `"Only the agent marks an Approve step done."` (the user tried `done` on an Approve step: its wrong-kind message), `"An answer needs text."`, `"Say what happened."` (`complete`/`fail` without text), `"Only an Approve step takes a Not before time."`.
- **Ops** (`apply_op`): `add` makes an open step (`addedAt` now, a new id); `edit` changes `text` (refused on an approved step: `"Withdraw the approval before changing this step."`; on a done Approve step: `"A done Approve step can't be changed."`) and `kind` (open steps only: `"Only an open step changes kind."`); `move` puts the step before another (or last); `remove` drops it. An agent can't edit, move or remove an Approve step that is approved or done (`"Agents can't change an approved or done Approve step."`). Caps and one-line text checked here.
