fixture spaces. Nothing in the repo was changed. Every finding below was either reproduced or traced
to the quoted lines; the confidence column says which. Fix suggestions are one-liners, not designs.

## Findings, most severe first

Severity: HIGH = data loss, corruption, security or a crash on a common path; MEDIUM = wrong behaviour on
a realistic path; LOW = edge case. Confidence: CONFIRMED = reproduced (R) or fully traced in code (T).

### HIGH

1. **One bad frontmatter file makes the whole space fail to open.** CONFIRMED (R).
   `backend/objectapp/frontmatter.py:148-169` (`parse_fm`) converts only `YAMLError` and
   `RecursionError` into `FrontmatterError`; `typedefs.py:177-186` (`read_raw`) and `space.py:1026-1030`
   catch only that and `OSError`. Two inputs escape: a sequence key (`? [a, b]\n: 1`, ruamel makes a tuple
   key, `_plain` turns it back into a list, the dict comprehension raises `TypeError: unhashable type`), and
   an integer scalar over 4300 digits (`ValueError: Exceeds the limit`). `Space.__init__` raises and the
   space cannot be opened at all. The same holds through the Trash: a trashed `.md` without its `.json`
   sidecar is parsed by `trash.py:160-166` (`_fallback_meta`, catches `OSError` only) from
   `purge_expired` during open. Fix: catch `(YAMLError, TypeError, ValueError, RecursionError)` in
   `parse_fm`, keep or stringify tuple keys in `_plain`, and treat any parse exception in `read_raw` and
   `_fallback_meta` as "read-only: frontmatter is not valid YAML".

2. **A read-only agent turn can escalate to full writes by delegating.** CONFIRMED (R, T).
   `api_agent_a2a_v1.py:188-205` (`POST /v1/agent/delegate`) never checks `token.scope`;
   `delegation.py:270-275` calls `headless.run_chat`, and `headless.py:178-180` mints the delegated run's
   token as `"read-write"` with no budget and no tool list. Proposal modes (`api_ai.py:290`, askBlock,
   tagBlock, tagObject, autofill, rephrase) get a `read` token, and `toolcatalog.run_tool_lists` only
   removes the write tools, so `delegate` stays allowed. Repro: a `read` token gets 403 on
   `POST /v1/objects` and 200 "completed" on `/v1/agent/delegate`, and the delegated CLI run has
   `write_body`, `set_properties`, `rename`, `trash` allowed. Fix: refuse `delegate` and `remote_call` for
   a token whose scope is not read-write, and have `run_chat` inherit the caller's scope and budget.

3. **An agent with the shell off can read every saved version of every page, excluded pages included.**
   CONFIRMED (R against the project's reference matcher in `fake_claude.py`, T).
   `agentrun.py:264` fences the state dir one level deep: `Read({s}/*)`, `Edit({s}/*)`. Version history
   is at `history.py:230` `<state>/history/<sha>/<key>/<stamp>.md` (full copies on every save) and deleted
   spaces at `spaces.py:357` `<state>/fake-trash`. `*` does not cross `/`, so `Read` of the history copy of
   a page with `excludeFromAI: true` is allowed while `Read` of the page itself is denied. `Edit` has the
   same gap (history files and `index.json` can be forged). Fix: deny `Read/Edit({s}/history/**)` and
   `({s}/fake-trash/**)` (the agent's own folder lives under `<state>/agents`, which is why `{s}/**` is
   not used), and add a test beside `test_fence_covers_the_cache_dir_override`.

4. **One non-UTF-8 file name turns several routes into 500s and breaks search indexing.** CONFIRMED (R).
   Names that are not valid UTF-8 are read with surrogateescape. `server.py` guards its answers with
   `SafeJSONResponse`, but `api_v1.py:341` (`/v1/query`), `/v1/changes`, `api_v1.py:462`
   (`/v1/object/backlinks`), and `searchindex.py:809` (`_snippets` passes the surrogate path to sqlite;
   `_query` at :682 catches only `sqlite3.Error`) do not. With `Pages/Caf\xe9 notes.md` present,
   `/api/search?q=Cafe`, `/api/v1/search`, `/v1/query`, `/v1/changes` and backlinks of anything it links to
   answer 500, and every index sync logs "The search index could not apply a change". Fix: use
   `SafeJSONResponse`/`_display_safe` in `api_v1*.py`; skip or encode surrogate paths in `searchindex`.

5. **Editing a nested list rewrites its structure.** CONFIRMED (R).
   `frontend/src/editor/document.ts:285-296` (`parseSourceBlock`) and `:222` (`contentKey`). The
   `@tiptap/markdown` list tokenizer lexes `1. a / - b / 1. c / - d / 2. e` with `1. c` as a sibling of
   `- b` instead of its child (plain `marked` nests it; reproduced with bare StarterKit + Markdown, so it is
   upstream). The loss check `contentKey` strips list markers and all whitespace, so the mis-nested parse
   passes as lossless and the block loads as an editable list. Unedited, the file is byte-preserved; one
   typed character anywhere in that list saves `1. a\n   - b\n   1. cZ\n     - d\n2. e\n`, re-parenting c
   and d. Patterns affected: an ordered list inside a bullet inside an ordered list (tight, loose, with
   task items, with `10.`). Fix: make the loss check structure-aware (compare per-item depth from a plain
   `Marked` lexer against the node tree, fall back to the raw block on a difference), or give the lists a
   CommonMark-faithful tokenizer as `extensions/taskListMarkdown.ts` does for to-do lists.

### MEDIUM

6. **An Agent Card can point the A2A endpoint at Object's own loopback API; chatting then POSTs into
   unauthenticated `/api` routes.** CONFIRMED (R). `a2a.py:315` accepts any http(s) interface URL;
   `server.py:704-715` lets a request with a loopback `Host` and no `Origin` through; `api_ai.py:119`
   `SaveChatRequest` has all-default fields, so the JSON-RPC body is accepted and a chat creates an
   "AI Chat" object in the open space. `api_remote_agents.py:258` only warns on *preview*; `add` (262)
   and `refresh` (299) store the endpoint silently, and `agents.py:780` drops the secret on a host change
   but accepts the new host. This is the M20 "Refresh" open item plus a loopback SSRF. Fix: refuse
   endpoint hosts that are loopback or the app's own base URL unless the card host is too; carry
   `preview_warnings` into `add` and `refresh`; refresh re-confirms a host change rather than switching.

7. **Every stdio MCP server in a run receives the turn's read-write `OBJECT_API_TOKEN` and every other
   server's secret.** CONFIRMED (R). `agentrun.py:466-471` (`_run_env`) puts the token, folder `${VAR}`
   secrets (`:350`) and gateway `OBJECT_MCP_*` secrets (`mcpgateway.py:203`) into the CLI's process
   environment, and the CLI starts every stdio server with that environment (the reference model
   `fake_claude.py:452` does exactly this). A third-party server from Settings > MCP servers or an agent
   folder's `.mcp.json` can read the space with full write access for the turn. Fix: pass each server only
   its own secrets through that server's `env` block in the run's `mcp.json`; keep `OBJECT_API_TOKEN` on the
   `object`/`object-agent` entries only.

8. **Non-finite floats reach the file and then make the object unreadable.** CONFIRMED (R).
   `space.py:890-897` (`_json_scalar`) accepts any float and Python's `json.loads` accepts `NaN` and
   `Infinity`, so `PUT /api/object/properties` with `{"updates": {"foo": NaN}}` writes `foo: .nan`; the PUT
   answers 500 and every later `GET /api/object?path=…` answers 500 (Starlette uses `allow_nan=False`).
   A hand-written `score: .nan` does the same on GET while the list route still shows the object. Fix:
   refuse non-finite floats in `_json_scalar` as `propvalues._encode_number` (`:512-517`) does, and map
   stored non-finite values to `None` in `_plain` or `_display_safe`.

9. **"Move batch to Trash" trashes an object another batch created at the recorded path.** CONFIRMED
   (R). `importers/batches.py:185-205`: the lookup at the recorded path compares only `(system, id)`, never
   the object's `batch`, and also accepts an object with no provenance block at all. Batch A creates
   `Pages/a.md`; the user deletes it; a re-run (batch B) creates it again; moving batch A to the Trash
   trashes B's object (`{'trashed': 1}`) and B's records still say "created". Fix: at the recorded path
   require `block["batch"] == batch`, fall back to `by_id`, and never trash a block-less object.

10. **An approved Work step with no queue entry is never picked up again.** CONFIRMED (R).
    `workqueue.py:29-31` and `workloop.py:121-127`: a `move` (the StepList drag has no state guard) or a
    no-op `edit` on an approved step withdraws its entry (`WITHDRAWN_CHANGED`) while the step stays
    `approved`; nothing re-creates an entry when it becomes current again and `_auto_check` only re-queues
    `open` steps. The user's only actions are decline or reopen. Fix: do not withdraw on a move or no-op
    edit (or reset the step to `open`), and have `_auto_check` re-queue a current `approved` step with no
    live entry.

11. **A FIFO in an import source tree hangs the scan forever.** CONFIRMED (R). `importscan.py:205-213`
    checks `is_symlink()` and `st_size` but never `S_ISREG`; `_text_or_none` opens the pipe and blocks.
    Reached by `POST /api/import/scan`, `POST /api/import/batches` and `agentwire.prepare()` at import
    start, so the import job sits in "preparing" and `Jobs` answers 409 to every further import until
    restart. `source._list_folder` already skips non-regular files. Fix: `stat.S_ISREG(lstat.st_mode)` in
    the walk, and the same guard in `_scan_zip` and the readers.

12. **An empty or blank import-scan path scans the server's working directory.** CONFIRMED (R).
    `api_importscan.py:29` and `api_v1_tools.py:584`: `Path("".strip())` is `.`, which exists and is not
    a space, so `POST /api/import/scan {"path": ""}` (also with a **read** v1 token) scans the cwd and
    returns its findings (`sub/creds.txt: password`). Started from the repo it walks `.venv` and
    `node_modules` at 100% CPU for minutes. Fix: reject an empty path before `expanduser()` (404, as
    `/import/preview` does).

13. **Creating an agent inside another agent's folder bricks both agents.** CONFIRMED (R).
    `agents.py:540-571` only checks space folders; `agentrun.py:274` (`nesting_problem`) checks all fenced
    folders but every turn of both the inner and the outer agent then answers "An agent folder can't be
    inside a space folder or hold one." Fix: refuse other agent folders, `<state>/agents/.trash` and
    `<state>/agents` itself at creation, and have `nesting_problem` name what it hit.

14. **Today view's now-line runs at twice real speed.** CONFIRMED (R, T). `frontend/src/work/views/
    TodayView.tsx:86-97` adds the time since mount to `now`, but `now` is already `WorkPage`'s live clock
    (`useNow()` ticks every minute). After an hour the line is two hours ahead and leaves the day range.
    Fix: derive `current` from `now` alone.

15. **A CSV import that fails part-way duplicates every object on retry.** CONFIRMED (R).
    `frontend/src/types/ImportCsvDialog.tsx:246-268`: `run()` restarts from row 0 and, for a new
    collection, creates the collection again. Fix: remember the first failed row and the created
    collection and resume from there.

16. **Calendar reload heuristic uses the UTC day, not the shown zone's day.** CONFIRMED (R).
    `frontend/src/calendar/useCalendarRange.ts:16-23` reads `start.slice(0, 10)` of a `…Z` value. In
    America/New_York a task set to Nov 7 23:30 is `2026-11-08T04:30Z`, so a Day view showing Nov 7 is not
    reloaded and the task stays missing. Fix: use `dayReader()`/`daySpan` from `views/dates.ts`.

17. **An indented (non-fenced) code block inside a list item is corrupted by any edit in that list.**
    CONFIRMED (R). `frontend/src/editor/preserve.ts:577-579, 608-611`: `preserveFenced` returns null for
    an indented block, so the fenced form is emitted at the wrong column; editing the item adds four
    spaces to the code, editing the code places the opening fence inside an indented block. Fix: re-emit
    indented at item indent + 4, or fence at the item's content column.

18. **A GFM task item in an ordered list loses its checkbox when edited.** CONFIRMED (R).
    `1. [ ] a` loads as an ordered item whose text is `[ ] a`; on save the brackets are escaped
    (`1. \[ \] aZ`). Fix: do not escape a leading box in an ordered item's first paragraph, or model
    ordered task items.

46. **Test helper race, the cause of the M24 loop "timing flake".** CONFIRMED (R).
    `workloop.py:234-242` (`wait_idle`, tests only) checks `not self._busy` and then `not self._can_start()`.
    `Env.acts()` calls `wake()` right before `env.idle()`, so the worker wakes between the two checks: the
    first sees the worker idle, the second sees the just-claimed entry as `running` (no longer pending),
    and `wait_idle` returns True while the run is in progress (instrumented: returns after 0.0 s with
    `_busy == True`). `test_not_marked_and_timeout` then reads `running` instead of `failed`;
    `test_not_before_and_reorder` is the same race under load. The loop itself behaves (the 2 s timeout
    fires and the entry ends `TIMED_OUT`). Fix: in `wait_idle`, re-read `_busy` after `_can_start()` (or
    require both to hold on two consecutive polls). Also, `TIMED_OUT` says "within 30 minutes" even when
    the timeout is patched.

## Not a bug, but relevant to "never write on read"

Opening a space does write under `.object/` and `.object-cache/` (built-in type JSONs and the v1 to v2
type migration with its backup, `frontmatter.json` and its `.gitignore`, and `purge_expired` deleting
Trash entries older than 30 days). No `.md` is touched: every file was hashed across an open of a space
with legacy folders, a BOM+CRLF file and an unterminated frontmatter, and only `.object/types/*.json`
and the backup changed.

## What was checked and found fine

- Text-file layer: majority line ending, BOM, surrogateescape round trip, atomic replace with mode
  kept, hard-link `create_new` and `move_no_overwrite`, Windows retry.
- Frontmatter edits: quotes, colons, comments, literal blocks, nested maps, anchors, flow mappings,
  U+2028, timestamps, BOM+CRLF, mixed endings, no trailing newline, empty and absent frontmatter; only
  touched lines change. Duplicate keys, tabs, merge keys and multi-document sources become read-only.
- Rename, relink, trash and restore: collisions, case-only rename, link-breaking titles, referrers in
  body and frontmatter, aliases and headings kept, code left alone, `(2)` on restore, manifests never
  overwrite. Conflict detection, concurrent writes and creates, watcher own-write suppression, link and
  search index consistency after rename.
- Path handling: `_rel`, media and attachment paths, export zip, trash ids, definition ids, history keys,
  upload names, import zip entries (absolute, drive, `..`, NUL, links, encrypted, nested limits), agent
  support paths, `reveal_file`.
- `LocalOnlyMiddleware`: Host forms, Origin on every unsafe method, upload content type, no websocket
  routes, no CORS; `OPTIONS`/`HEAD` 405. XSS: raw HTML escaped in both markdown renderers, `safeHref`
  scheme allowlist, KaTeX `trust:false`, Mermaid `strict`, Tiptap link `openOnClick:false`.
- v1: every write route answers 403 to a read token (except finding 2 and the by-design scans); excluded
  and template objects answer 404 or are absent on every v1 read and write route (except the `values`
  leak in 23); token hashes with constant-time compare; budget spent under a lock.
- `claude` subprocess: prompt on stdin, no `shell=True`, process group killed on done/timeout, reader
  threads, per-turn timeout, missing CLI handled; the agent fence otherwise (space folders as given and
  resolved, other agents, trash, remote folders, cache dir, credentials file, `.mcp.json` edits denied,
  `claudeMdExcludes`); A2A client (no redirects, size caps, deadlines, token redacted); gateway secrets
  0600 and only referenced from `mcp.json`; schedules (dedupe, DST, daily minimum); learning undo checks
  the current file equals `after` before writing.
- Import writer path safety, provenance matching, "changed in both" handling, filing pass fences;
  readers parse with `resolve_entities=False`; Work rules table, approval gate, loop crash detection,
  day and board boundaries in the space's zone.
- Editor: 68 tricky bodies round-trip byte-identical when unedited; editing one block leaves every other
  block's bytes alone except findings 5, 17 and 18; autosave debounce, in-flight queue, echo
  suppression, path switch, unmount, 409 and external-edit paths; API client turns every 4xx/5xx into a
  typed error; shortcuts guard editable targets; zustand selectors stable.
- Feature UIs: filter, sort, group and date engines (parity with `automation_filter.py`), kanban,
  calendar and timeline drag, whiteboard save queue and ink merge, AI chat SSE and abort, import dialog
  guards, every `setInterval` cleared on unmount.
