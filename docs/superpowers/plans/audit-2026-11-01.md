## Fix first (data loss, security, or the app breaking)

### Back end

1. **One file with deeply nested YAML stops the space from opening.** `parse_fm` (`frontmatter.py:117-120`) catches only `YAMLError`; a value such as `a: [[[[…` with 500+ brackets raises `RecursionError` from ruamel's composer, `read_raw` (`typedefs.py:157`) catches only `FrontmatterError`, and `Space.__init__` (`space.py:733-736`) only `OSError`, so `Space(root)` dies and the whole space is unopenable until the file is removed by hand. `rescan_file`/`read` raise too (`GET /api/object` → 500); the watcher survives but never indexes it. Fix: catch `RecursionError` in `parse_fm`/`_load_rt` and raise `FrontmatterError`, so the file opens read-only like other bad YAML. (`backend-core/probe2_crash_perf.py`, `probe6_http.py`)
2. **A frontmatter with a top-level merge key (`<<: *anchor`) opens read-write but every save fails with 404.** `_key_spans` (`frontmatter.py:219`) calls `data.lc.key(k)` for every key; merged-in keys have no line info and raise `KeyError`, which escapes `set_keys` → `_write` (`space.py:1573-1580`), and the route maps `KeyError` to "No object at …" (`server.py:975`); `_rewrite_other` (`space.py:1660`) reports "The file no longer exists". Fix: detect `data.merge` (or catch `KeyError`) in `_load_rt`/`_key_spans` and raise `FrontmatterError` (read-only with a reason). (`probe2`, `probe6`)
3. **Collections and queries with a non-Latin name cannot be created: 500.** `typedefs.slug` (`typedefs.py:110-118`) keeps non-ASCII letters, but `JsonStore.path` (`jsonstore.py:35`, `_ID_RE = ^[A-Za-z0-9][A-Za-z0-9._-]*$`) rejects the id with `ValueError`, uncaught in `create_collection`/`create_query` (`space.py:935`, `:1358`). `POST /api/collections {"name":"日本語"}` (or `"ü"`, `"데이터"`) → 500, nothing written. Types accept such ids (`types/日本語.json` is written) but `GET/PUT /api/views/日本語` then says the id can't be used as a file name, so the type has no saveable views. Fix: make the two agree (a Unicode `_ID_RE` with a length cap, e.g. `^[^\W_][\w.-]{0,99}$`; or `slug` falling back to an ASCII id when nothing survives), and apply the cap to ids from URLs. (`backend-api/fuzz_routes.py`)
4. **500 on `\x00` in a space path, and 503 for an over-long path.**
   - `spaces.normalize` (`spaces.py:79-81`) does `Path(...).resolve()`, which raises `ValueError: embedded null character`, uncaught in `POST /api/spaces/open` (`server.py:876`), `DELETE /api/spaces` (`:891`), `POST /api/spaces` (`spaces.py:247`), `POST /api/spaces/delete` (`:377`) and `/spaces/switch`. Fix: reject NUL in `normalize` and map `ValueError` → 404/422.
   - `Space._rel` (`space.py:1484`) raises `OSError(ENAMETOOLONG)` for a 300+ character component, which the global `OSError` handler (`server.py:787`) turns into **503 "The file system refused the change"** on every path-taking route (29 routes in the fuzz), and `PUT|DELETE /api/queries/{300-char id}` the same via `json_revision`. Fix: in `_rel`, `except OSError: raise ValueError` (→ 400); cap `_ID_RE` length. (`fuzz_routes.py`)
5. **`POST /api/attachments/open` hands OS-executable files to the OS.** `media.REFUSED_OPEN_EXTENSIONS` (`media.py:211`) misses `.pif .scf .msc .inf .ws .sct .application .pyw .py` (Windows runs `.py`/`.pyw` when Python is installed, as on Gene's PC) and `.desktop .appimage .run` (`xdg-open` launches them). A space received from someone else can carry such an attachment. Fix: extend the set (`pif scf msc inf ws wsc sct application gadget py pyw pyz desktop appimage run bin iso dmg pkg`), or whitelist openable kinds. (`backend-api/security_checks.py`)

### Editor

6. **Tilde-fenced code blocks are corrupted by edits.** `preserve.ts:457-472` `preserveLines` aligns regenerated lines against the baseline, and `nodes/codeBlock.ts:60` `codeFence` counts only backtick runs. In `~~~\ncode\n~~~`, typing a ```` ``` ```` line inside **replaces the typed line with `~~~`**; typing `~~~` inside saves `~~~\ncode\n~~~\n~~~\n`, which reloads as two code blocks with the typed line gone. Backtick fences are fine. Fix: for `kind === 'code'` keep the original fence character, compute the fence length for that character (extend `codeFence` to `~`), and align only the inner lines. (`editor/zz_audit_edits2`)
7. **A paragraph beginning with 4+ spaces or a tab reloads as an indented code block, dropping the indentation.** `textEscapes.ts:59` `escapeLineStarts` has no rule for leading whitespace; `    four spaces` (or `\tTabbed`) is saved verbatim, reloads as `codeBlock "four spaces"`, and the next save writes a fenced code block. Fix: on a paragraph's first line, write a leading run of ≥4 spaces or a tab as `&nbsp;` + rest (`NbspEntity` reads it back). (`zz_audit_edits`)
8. **Copy or cut of a block selection and paste back destroys the blocks' structure, and pasted Markdown is never parsed.** `extensions/blockSelection.ts:575-581` `onClipboard` sets only `text/plain` (the blocks' Markdown) and `preventDefault()`s; there is no `clipboardTextParser`, so ProseMirror splits the text into one paragraph per line. Copy `- a\n- b` as blocks and paste → `paragraph "b- a" | paragraph "- b"`, saved as `b- a\n\n\- b`; pasting a list, heading and table from outside gives seven escaped paragraphs. Cut + paste therefore loses structure (only undo restores it). HTML paste works. Fix: a `clipboardTextParser` that builds a `Slice` from `editor.markdown.parse(text)` (fall back to the default when the text has no Markdown syntax), and/or write `text/html` in `onClipboard`. (`zz_audit_perf2` "paste")

### Whiteboard

9. **Text typed in a node editor is lost when the editor unmounts without blur or Escape.** `nodes/TextBlockEditor.tsx:41-48` commits only on blur/Escape, `edges/EdgeLabel.tsx:57-61,79` the same; nothing commits on unmount and `editingId` stays set. The canvas uses `onlyRenderVisibleElements` (`WhiteboardCanvas.tsx:934`), so a node or edge being edited that leaves the viewport (wheel pan with the pointer off the node, Space+drag, Shift+1 fit, a window resize, a frame "Play") is unmounted and the text is gone. Fix: keep the latest Markdown in a ref via `onUpdate` and commit from the effect cleanup (or Tiptap `onDestroy`) when not yet committed; same for `LabelInput`; clear `editingId`. (`whiteboard/zz_audit_editors`)
10. **One stroke at the client's 20,000-point cap produces a path over the server's 1 MB cap, after which every ink save fails.** `ink/inkModel.ts:566` `MAX_STROKE_POINTS = 20_000` vs `whiteboardink.py:37` `MAX_D_BYTES = 1_000_000` (422 at `:126`). A 20,000-point stroke gives `d` = 1.33 MB (12,000 points: 0.80 MB). It stays pending, every later stroke merges into the pending set, and nothing is written until the big stroke is erased; the only sign is the "Could not save the ink" toast. Needs ~80–170 s of continuous pen input at 120–240 Hz. Fix: split at ~10,000 points (or by `d` byte length) in `splitPoints`/`InkLayer.tsx:285`, or raise the server cap; both sides must agree. (`zz_audit_ink`)

### Views and properties

11. **A table number edit is silently lost after a failed write.** `NumberCell.tsx:49-50` sets `last.current = n` before `onChange`; `TableLayout.tsx` `fail()` (non-409 branch, ~243) only shows a notice and doesn't reload the row, so `last.current` keeps the failed value and retyping the same number is skipped (`n === last.current`): nothing is sent and no notice shows. Fix: in `NumberCell` `onFocus` set `last.current = value`, or have `fail` reload the row on every error. (`views/audit_comp` D1)
12. **Kanban over several types that share a key of different kinds writes a label list into a plain-text property.** `KanbanLayout.tsx:107` picks `groupDef` from the first type, and `group.ts:290` `rowBuckets` uses one def for every row. With type A `status: label` and type B `status: text`, B's "Done" lands in Other, and dropping it on "Done" writes `{status: ['Done']}` on B. Fix: resolve the def from the row's own type in `rowBuckets`/`valueForGroup` (as `matchFilter` does) and refuse the drop when the kinds differ. (`audit_pure` A2)
13. **Text grouping truncates at 500 characters and a drop writes the truncated text.** `group.ts:108,222` `textBucket` slices the value to 500 and uses it as the label; `valueForGroup` (~515) writes `group.label`. Two values sharing a 500-character prefix also merge into one column. Fix: keep the full text as the group id and write value; truncate only the displayed label. (`audit_pure` A3)
14. **CSV import stores percentages 100× too large.** `ImportCsvDialog.tsx:125` calls `parseNumberInput(t)` with no format, while `NumberCell` edits a percentage property in percent: `csvValue(pctDef, '25')` = 25 (shown as 2,500 %). Fix: pass `def.options.numberFormat` and apply the cell's `fromPercent` shift. (`audit_pure` C1)

### Shell

15. **After a dropped connection the app misses every change event and never resyncs.** `api/client.ts:311-324` `ensureSource` registers only a `change` listener (no `open`/`error`), and the server's `EventHub.subscribe` (`server.py:255-268`) has no replay or `Last-Event-ID`. When the server restarts, the laptop sleeps or the stream drops, the browser's `EventSource` reconnects silently and every event in between is gone: sidebar counts, tab labels, pins, calendar, references, graph and definitions stay stale until a reload, and an open `ObjectView` only learns of another window's save through a 409 dialog. Fix: `onerror` sets a flag; `onopen` after a drop emits a synthetic resync (one event per kind the hooks listen for: `types` with path `*`, plus `ui`, `collections`, `queries` with a non-own origin); optionally event ids with replay of the last N. (`shell/zz_audit_sse`)
16. **Two windows of one space overwrite each other's tabs and recent list.** `nav/tabs.ts:536-547` (zustand `persist`, key `object.tabs:<root>`, hydrated once) and `nav/recent.ts`: each window writes its whole `{tabs, activeId}` on every navigation, so the other window's tabs are gone from storage and lost at the next start. Fix: listen to the `storage` event for the space key and merge (union by id, keep own `activeId`), or rehydrate on `visibilitychange`. (`zz_audit_shell` "tabs in two windows")

## Back end: other bugs

- **Rename rewrites a `# Old title` line inside a code block.** `rename_object` (`space.py:2229-2233`) runs `_HEADING_RE` over the whole body; a `# Alpha` shell comment in a fence becomes `# Beta`. Fix: skip matches inside `relink.code_ranges(body)`. (`backend-core/probe1_frontmatter_writes.py`)
- **Every app save changes the file's permission bits to 0600.** `atomic_write` (`textfile.py:139-147`) replaces the file with a `mkstemp` temp (mode 0600), so a 0644/0664 file loses group/other read (shared folders, Syncthing, multi-user machines); JSON stores and history too. Fix: `fchmod` to the existing mode before the replace; new files `0o666 & ~umask`. (`probe1`)
- **`rename_key` on an explicit-key form (`? status\n: Done`) produces unreadable YAML.** `_key_token_end` (`frontmatter.py:330-331`) returns `len(line)` when the key line has no `:`, so `rename_key` (`:357-361`) slices off the newline and writes `? state: Done`. Reachable from `change_type` mapping renames (`space.py:2514`). Fix: exclude the trailing newline (or fall back to `set_keys`) and verify `parse_fm(out)` before returning. (`probe2`)
- **Restoring a deleted template loses its registration.** `delete_object` unregisters it (`space.py:2985-2986`, drops it from `templates.ids` and clears `defaultTemplateId`); `_restore_object_entry` (`:3417-3429`) only puts the file back, so it is no longer the type's default. Fix: record the ids index and `defaultTemplateId` in the trash meta and re-apply on restore. (`probe3`, `probe4`)
- **A trash object whose `.json` meta is missing becomes invisible and immortal.** `Trash.object_meta`/`object_ids` (`trash.py:144-147`, `201-206`) require both files, so the `.md` is neither listed, restorable nor purged. Fix: list `*.md` without meta with fallback fields and restore into the root. (`probe3`)
- **`ui.json` patches don't re-check for an external edit before replacing** (`uistate.py:540`, `atomic_write` with no `check`), unlike `JsonStore.write` and `spaceconfig.patch`; an external edit between the read and the replace is overwritten. Fix: a `check` that re-hashes against `current` and raises `RevisionConflict`, as `jsonstore.py:503-511`. (`probe4`)
- **Watcher: templates under an externally moved or renamed folder stay in the index.** `_touch_folder` (`watcher.py:195-204`) re-checks `space.list()`, which excludes templates. Hidden on Linux (per-file inotify events), not on Windows (one directory event). Fix: iterate `space._summaries` under the lock. (`probe4`)
- **`POST /api/images` has no size or emptiness check.** `post_image` (`server.py:1612-1613`) reads the whole body; `post_attachment` enforces the 100 MiB limit (413) and rejects empty uploads (422). A 101 MiB or empty image → 201. Fix: the same check. (`backend-api/security_checks.py`)
- **Recurring-task catch-up writes thousands of log lines.** `plan_occurrence` (`api_tasks.py:206`, `_missed(..., 10_000)`) logs every missed occurrence on `catchUpThroughNow`; a daily task dated 1800 produced a 10,001-line `occurrenceLog` (420–520 KB) in 1.3–3.1 s. Object caps the missed dialog at 99. Fix: cap what is logged, or one summary line for the range. (`backend-api/edge_dates.py`)
- *(code reading)* **Misleading 503 text for a permission error:** the global `OSError` handler (`server.py:787-797`) says "A file is in use by another program" for every `PermissionError` (EACCES on macOS/Linux). Use that text only for Windows `winerror == 32`. `api_spaces_m8.py:66` answers a bare 500 for other `OSError`s.
- **Second launch on a taken port shows nothing useful.** With the port bound, uvicorn logs "address already in use", the server thread ends, `_wait_until_up` (`__main__.py:142-149`) times out and `main` still opens a window on the URL. Fix: check the thread after `_wait_until_up` and exit with a message, or pick another port.
- **A board whose `.md` has malformed or no frontmatter answers 422 "isn't a whiteboard"** although the sidecar is intact (`whiteboardstore.py:214-223` `_board_md` compares `summary.type`; a read-only `.md` is typed `page`). Fix: also accept an object with `<stem>.whiteboard.json` beside it and serve the board read-only. (`whiteboard/test_wb_backend_repro.py`)
- **A whiteboard sidecar's BOM and CRLF are not preserved** (`whiteboardfile.py:358` reads `utf-8-sig`, writes LF without BOM). Minor (app-owned file). Fix: sniff and re-apply in `_save_sidecar`. (`test_sidecar_bom_crlf_kept`)

- **B1.
