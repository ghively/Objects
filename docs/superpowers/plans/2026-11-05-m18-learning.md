**Goal.** Each agent learns, visibly and undoably. It saves memories (`MEMORY.md`, `USER.md`) and writes and improves its own skills with Object's `memory` and `skill_manage` tools. Every change goes to its ledger with the before and after content, and the Skills tab can undo each one. After a reply, background reviews decide what to save or improve, and the chat shows "Learning…". A curator marks unused skills stale and then archives them while Object is idle, and can merge overlapping skills when asked. The agent can search its own past chats. Each chat's prompt carries a frozen snapshot of the memory files as they were when the chat started.

**Architecture.** The back end gets these modules:

- `learningmodel.py`: the constants, the `learning` settings in `agent.json`, the ledger entry and `usage.json` schemas.
- `ledger.py`: `.object-agent/ledger.jsonl`, append and read.
- `agentmemory.py`: the two memory files, the `memory` operations, the per-chat snapshot and the two run contributors that append it and the learning guidance.
- `agentskills.py`: skills on disk, `usage.json`, the enforced `skill_manage` rules, archive/restore/pin, and the per-run read memo.
- `learnundo.py`: Undo of one ledger entry.
- `chatsearch.py`: the SQLite FTS5 index over the agent's transcripts in `.object-agent/cache/sessions.db`.
- `reviews.py`: the two counters, the three prompts, the review runner, the review contributor and the turn watcher.
- `curator.py`: the idle clock, the deterministic pass, the optional consolidation run and the scheduler.
- `agent_tools_learning.py`: the five MCP tools, registered in M17's `object-agent` server.

## Global Constraints

- Every model call, reviews and the curator included, is a `claude` CLI run under Gene's own login, built by `agentrun.build_run`. Object never reads `~/.claude/.credentials.json` or any Claude token and never calls Anthropic's API. No network client in `learningmodel`, `ledger`, `agentmemory`, `agentskills`, `learnundo`, `chatsearch`, `reviews`, `curator`, `api_learning`, `api_learning_v1` or `learnhooks`. `agent_tools_learning.py` uses M17's `ObjectClient` (httpx to the loopback app only).
- The server binds `127.0.0.1` only.
- **Memory tool** `memory`: actions `add`, `replace` (by unique substring), `remove` (by unique substring); target `memory` (`.object-agent/memory/MEMORY.md`) or `user` (`.object-agent/memory/USER.md`). Entries are separated by a line `§`.
- **Caps**: MEMORY.md **2,200** characters, USER.md **1,375** (defaults, settable per agent). A write past the cap fails with the current entries listed. Writes are atomic and logged in the ledger.
- **Skills tool** `skill_manage`: `create`, `patch` (old/new string, in SKILL.md or a support file), `edit` (whole file), `write_file` / `remove_file` (support files), `archive` (with `absorbed_into` when merged). Rules enforced by the tool: a `patch` or `edit` must follow a read of that skill in the same run; names at most **64** characters; the index description at most **60** characters; SKILL.md at most **100,000** characters; support files at most **1 MiB**.
- Every memory and skill change goes to `.object-agent/ledger.jsonl` with the before and after content. The Skills tab offers **Undo** per change. Skills the agent creates are marked `created_by: agent`; skills Gene writes are `created_by: user`.
- `skills_list` and `skill_view`; `skill_view` bumps `.object-agent/usage.json`.
- **Background reviews.** Two counters per chat: user turns since the agent last used `memory`, and tool calls since it last used `skill_manage`; using the tool resets its counter. Interval default **10** each; **0** switches that review off. The review runs **after the reply has been shown**, as a separate `claude -p` run with the same model, the same system prompt, the chat's messages, and one of three prompts (memory, skills, both).
- A review may use only `memory` (when the memory counter fired), `skills_list`, `skill_view`, `skill_manage` and read-only Object tools; at most **16** tool steps.
- The skills prompt asks the agent to prefer, in order: patch a skill it used this chat; patch an existing broader skill; add a reference/template/script file to one; only then create a new broader skill (not one per chat); to turn Gene's corrections into skill rules; never to delete a skill; to skip environment failures and dead ends.
- The chat shows a small "Learning…" line while a review runs and "Saved 1 memory, updated 1 skill" after (click opens the change). A review never blocks the next turn. "Learn from this chat" in the chat's `…` menu runs a review on demand.
- **Curator**: runs when Object has been idle for at least **2 hours** and the last run was at least **7 days** ago (both settable; on by default).
  - Deterministic pass (no model): an agent-created skill not used for **14** days becomes **stale**, for **30** days **archived** (moved to `.object-agent/skills-archive/`, restorable).
  - Pinned skills, skills Gene wrote, and skills a schedule uses are never touched. A skill never used and younger than 14 days is never archived.
  - Optional consolidation pass (**off by default**; "Tidy up now" on the Skills tab runs it once): a `claude -p` run that merges overlapping skills into broader ones (archiving the absorbed ones with `absorbed_into`) and writes a short report shown on the Skills tab.
  - Every curator change is in the ledger and undoable.
- **Chat search** `session_search`: full-text search over the agent's own transcripts (`.object-agent/cache/sessions.db`, SQLite FTS5, rebuildable from `.object-agent/sessions/`), returning matching chats with snippets, and reading a chat by id. No model call.
- **Memory snapshot**: each turn appends MEMORY.md and USER.md **as they were when the chat started** (frozen per chat), before Object's standing guidance. The agent's own memory writes take effect in its next chat.
- **Review model**: the chat's model unless the agent's Learning tab names a review model.
- **Hidden learning is an anti-goal.** Everything an agent learns is visible and editable in Object, and nothing it learns is lost without a way back: no M18 code deletes a skill or a memory file. Archive, Undo and Gene's edits all keep a ledger entry with the before content.
- The agent changes its skills and memory only through Object's tools. M17's `PROTECTED` deny rules on `CLAUDE.md`, `.claude/**` and `.object-agent/**` stay. Gene edits them freely, in Object or any editor.
- "Exclude from AI" keeps its promise: reviews get only read-only Object tools, which hide excluded pages and templates; no M18 route reads a space file.
- **File safety for agent files**:
  - every write is atomic (`textfile.atomic_write`);
  - a memory file or SKILL.md that has a BOM or CRLF keeps them (`textfile.encode_like`);
  - `usage.json` and `agent.json` keep unknown keys;
  - the ledger is append-only, one write per entry, with a lock per folder;
  - no write goes through a symlink or junction out of the skill's folder.
- **Never write on read**: listing skills, reading memory, the ledger or a review's state, and opening the Memory, Skills or Learning tab write nothing. Writes that a search makes go only to the rebuildable `.object-agent/cache/` (gitignored by M17's `.gitignore`).
- Everything is unlocked: no badge, limit or gate.
- Tests write only to temp folders: `OBJECT_STATE_DIR` is a temp folder (conftest's autouse fixture). Nothing writes to `~/.claude` or the real state dir. Fixtures are synthetic.
- Live CLI tests run only with `OBJECT_LIVE_CLAUDE=1`, with `--no-session-persistence` and the `haiku` alias.
- No product or project names other than Object and Claude Code in code, tests or strings.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

These are the inputs and failure modes the spec implies that no single task's happy path exercises, most likely first. Each one's test is listed in its owning task.

1. **A review that reaches past its scope.**
   - A skills-only review calling `memory`; a review calling a write tool, a built-in (`Read`, `Bash`), the CLI's `Skill` tool, `session_search` or a folder MCP server.
   - A 17th tool call.
   - A review that forks the chat's session and changes the chat's own session id, or adds an assistant line to the transcript.
   - A review that blocks or fails the next turn of the same chat.
   - A proposal-mode turn (or a run whose purpose isn't `chat`) triggering a review.
   - Tests: `test_m18_reviews.py::test_review_tool_lists_by_kind`, `::test_review_token_refuses_tools_outside_its_set`, `::test_seventeenth_step_is_refused`, `::test_review_forks_and_leaves_the_chat_alone`, `::test_next_turn_runs_while_a_review_runs`, `::test_only_chat_turns_trigger_reviews` (T7).
2. **Undo that loses or overwrites something.**
   - Undo of an entry whose file changed since; undo of an undo; undo of a create (the skill must survive, archived); undo of an archive when a same-named skill exists again; undo of a curator archive.
   - A torn last ledger line.
   - A chat turn and a review writing the same memory file at once (no lost update).
   - Tests: `test_m18_skills.py::test_undo_refuses_when_changed_since`, `::test_undo_of_undo_and_of_create`, `::test_undo_archive_name_taken` (T3); `test_m18_memory.py::test_concurrent_adds_lose_nothing`, `test_m18_memory.py::test_torn_ledger_line_is_skipped` (T2).
3. **Skill paths and names that escape or collide.**
   - `../x`, `C:/x`, `/x`, a backslash, `SKILL.md` through `write_file`, a path outside `references/`, `templates/`, `scripts/`, a Windows reserved name (`con.md`), a name with upper case or spaces, a 65-character name.
   - A symlink or junction inside a skill folder pointing into a space folder.
   - Archiving into an archive that already holds that name; restoring onto an active name.
   - Tests: `test_m18_skills.py::test_bad_paths_and_names_are_refused`, `::test_no_write_through_a_link`, `::test_archive_and_restore_collisions` (T3).
4. **The curator touching what it must not.**
   - Pinned, `created_by: user` (or no `created_by`), a skill a schedule uses, a never-used skill younger than 14 days, a skill whose only use was through the CLI's own `Skill` tool, an agent with the curator off, the default agent before its folder exists.
   - Idle measured wrongly: the events stream, `/api/_test/*` and a running turn or review must not count as activity / must count as busy.
   - Tests: `test_m18_curator.py::test_never_touched`, `::test_native_skill_use_counts_as_use`, `::test_idle_clock_ignores_events_and_test_routes`, `::test_busy_while_a_turn_runs` (T8); `test_m18_reviews.py::test_native_skill_tool_bumps_usage` (T7).
5. **The frozen snapshot and the caps.**
   - A memory written mid-chat must not change that chat's appended prompt, also after a server restart and on a fresh replay (an expired session); a new chat sees it.
   - Caps counted in characters, not bytes (non-ASCII text); a CRLF or BOM file keeps both.
   - A file Gene made longer than the cap: the agent can still shrink it with `replace` or `remove`, but not `add`.
   - An entry holding a line `§`.
   - Tests: `test_m18_memory.py::test_caps_count_characters`, `::test_over_cap_file_can_shrink`, `::test_entry_with_a_section_line_is_refused` (T2); `test_m18_reviews.py::test_snapshot_frozen_per_chat` (T7).

## Contract (T1)

### Storage

Everything lives in the agent's folder (M17's layout, spec section 1). Review state is kept only in the transcript; curator state only in `usage.json`.

| What | Where | Written by |
|---|---|---|
| Memory | `.object-agent/memory/MEMORY.md`, `.object-agent/memory/USER.md`: entries joined by `"\n§\n"` (UTF-8; an existing file's BOM and line endings kept). Absent means empty; the folder is made by the first write. | `agentmemory` (the tool, Gene's edits, Undo) |
| Skills | `.claude/skills/<name>/SKILL.md` (+ `references/`, `templates/`, `scripts/`). SKILL.md front matter: `name`, `description`, and `created_by: agent` for skills the agent created. No `created_by` reads as `user`. | `agentskills` |
| Archived skills | `.object-agent/skills-archive/<name>/` (the folder, moved). A taken name gets ` (2)`, ` (3)`… | `agentskills.archive` / `restore` |
| Ledger | `.object-agent/ledger.jsonl`, one `LedgerEntry` per line, append-only. A line that doesn't parse is skipped. | `ledger.append`, called only by `agentmemory`, `agentskills`, `learnundo`, `curator` |
| Usage and curator state | `.object-agent/usage.json` (schema below), `jsonstore.dump_json`, unknown keys kept | `agentskills` (uses, state, pin), `curator` |
| A chat's memory snapshot | a `memory` line in the chat's transcript, written once, before the chat's first run | `agentmemory.snapshot_for` |
| Review state | two `review` lines in the chat's transcript (start and end, same `id`) | `reviews` |
| Chat search index | `.object-agent/cache/sessions.db` (SQLite FTS5). Rebuildable; deleted and rebuilt when unreadable or of another `INDEX_VERSION`. | `chatsearch` |
| Run read memo | in memory only, keyed by the run token's `id`, dropped with the token | `agentskills.MEMO` |

```jsonc
{"type":"review","id":"<ULID>","state":"done","summary":"Saved 1 memory, updated 1 skill","entryIds":["<ULID>"],"message":null,"at":"…"}
```

### Ledger entry (`learningmodel.LedgerEntry`, pydantic; `LedgerEntry` in `types.ts`)

```jsonc
{
  "v": 1,
  "id": "01JC…",                       // ULID
  "at": "2026-11-05T09:00:00.000Z",
  "target": "memory",                   // "memory" | "user" | "skill"
  "action": "add",                      // memory: add | replace | remove | edit (Gene's whole-file save)
                                        // skill:  create | patch | edit | write_file | remove_file | archive | restore
                                        //         | stale | active | pin | unpin
                                        // either: undo
  "skill": null,                        // the skill's name, for target "skill"
  "file": null,                         // "SKILL.md" or e.g. "references/x.md", for file changes
  "before": "…", "after": "…",          // the whole file's text before and after (null: no file); null for state-only actions
  "encoding": "text",                   // "base64" when a removed support file wasn't UTF-8 (before holds base64)
  "absorbedInto": null,                 // archive only
  "source": {"kind": "chat", "agentId": "assistant", "chatId": "01J…", "run": null},
                                        // kind: chat | review | curator | user | undo; run = the review or curator run id
  "undoes": null                        // for action "undo": the id of the entry it undid
}
```


History lines (`ledger.line`, our strings):

- memory: `Saved a memory`, `Changed a memory`, `Removed a memory`, `Edited the memory file`; for target `user` the same with `about you` added (`Saved a memory about you`).
- skills: `Created the skill '{skill}'`, `Patched '{skill}'` (`… in {file}` for a support file), `Rewrote '{skill}'`, `Added {file} to '{skill}'`, `Removed {file} from '{skill}'`, `Archived '{skill}'` (`… into '{absorbedInto}'`), `Restored '{skill}'`, `Marked '{skill}' stale`, `Marked '{skill}' active`, `Pinned '{skill}'`, `Unpinned '{skill}'`.
- `Undid: {line of the undone entry}`.

Every entry can be undone, undo entries included. Whether the files still match is checked when Undo is pressed, not when the list is shown.

### `usage.json` (`learningmodel.UsageFile`)

```jsonc
{
  "v": 1,
  "skills": {
    "rack-labels": {"uses": 3, "lastUsed": "…", "createdAt": "…", "state": "active", "pinned": false,
                    "archivedAt": null, "absorbedInto": null}
  },
  "curator": {"lastRunAt": null, "lastConsolidatedAt": null,
              "report": null}                 // {"at", "runId", "text"} of the last consolidation pass
}
```

- `state` is `active` or `stale`. "Archived" is where the folder is (`skills-archive/`), never only a flag.
- A skill with no entry is `active`, `uses: 0`, `lastUsed: null`, `pinned: false`. Its `createdAt` is its ledger `create` entry's `at`, else the first time the curator saw it (written then, by the curator).

### Fake `claude` (T1, `backend/tests/fake_claude.py`)

M10's, M16's and M17's markers are unchanged. These are added and documented in its docstring (built: the log line's `prompt` field is what the fake read on stdin; "stdin" in the tests below means that field):

- The log line gains `forkSession` (bool), `noSessionPersistence` (bool) and `resume` (the id or null).
- `--resume <id> --fork-session`: the `init` event's session id is a new UUID; the original isn't reused.
- `FAKE:mcp:<server>:<tool>:<json args>` in the prompt (one or more, run in order). The fake starts that server from the run's `--mcp-config` (stdio: its `command`, `args` and `env`, with `${VAR}` filled from the fake's own environment) with the `mcp` client library, calls the tool, and emits the `tool_use` and its `tool_result` (`is_error` for a tool error). A tool that `--disallowedTools` names, or that isn't in `--allowedTools`, isn't called: its result is "Permission to use {name} has been denied." (M17's matcher).
- `FAKE_CLAUDE_REVIEW_ACTIONS` (environment, a JSON list of `{"server", "tool", "args"}`): when the prompt holds the review prompts' first line ("Look back over this chat."), the fake runs these calls as if they were `FAKE:mcp` markers. `FAKE_CLAUDE_CURATOR_ACTIONS` does the same for the consolidation prompt's first line ("Tidy up your skills."). `FAKE_CLAUDE_REVIEW_SLEEP` (seconds) delays the answer; `FAKE_CLAUDE_REVIEW_FAIL=1` makes it write to stderr and exit 1 instead.
- `FAKE:skilltool:<name>`: emits a call of the CLI's own `Skill` tool with input `{"skill": "<name>"}` and a result (no MCP).

## Our calls

1. Learning settings live in M17's reserved `agent.json` `learning` key, with three keys added for the "settable" curator numbers and the consolidation switch (`curatorIdleHours`, `curatorEveryDays`, `consolidate`). Readers fall back to the default per key; a dedicated `PUT /agents/{id}/learning` validates them. The ranges are ours.
2. The frozen snapshot is a `memory` line in the chat's transcript, written before the chat's first run. Reviews of that chat use it too. The CLI's own recorded system prompt (`--system-prompt-snapshot`, default on) keeps resumes stable as well.
3. Review state lives in the transcript as two `review` lines (start and end), and the counters are computed from the transcript, so nothing else is stored and they survive restarts. A review's start resets the counters of its kinds whether or not the agent saved anything; otherwise a review would fire after every later turn.
4. A review resumes the chat's session as a fork (`--fork-session`, `--no-session-persistence`), which gives the spec's "same system prompt, the chat's messages" without touching the chat's session. When the resume fails it replays the transcript in a fresh run.
5. "At most 16 tool steps" is enforced by the run token's budget: every Object tool call is one `/api/v1` call, and the 17th answers 429. A review can only call Object tools (every built-in is disallowed), so the budget covers all its steps. `--max-turns` isn't used (it isn't in `--help`).
6. The review's tool set is enforced twice: by the CLI's allow and deny lists, and by the token's `tools` on the learning routes. It is also cut to what the agent has switched on. Folder MCP servers are left out of reviews and curator runs.
7. Reviews follow `chat`-mode turns only, not the proposal modes. At most one review runs per chat and two in all. A review that would start while one runs for that chat is skipped, and the counter fires again next turn.
8. "Learn from this chat" runs the "both" prompt with memory allowed, whatever the counters say.
9. The chat learns of reviews through `agentLearning` change events and `GET …/reviews`, so the turn's stream is unchanged and ends at `done`.
10. The summary's wording extends the spec's example: "Saved n memories", "changed n memories", "created/updated/archived n skills", "Nothing new to learn".
11. A skill's `created_by` lives in SKILL.md's front matter, so it travels with the skill. No `created_by` means Gene wrote it. A skill the agent made stays `agent` after Gene edits it; Pin protects it from the curator.
12. Pinned state, use counts, the stale mark, archive details and the curator's last run and report live in `usage.json`. Archived means "in `skills-archive/`".
13. Skill names follow Claude Code's form: lower case, digits and hyphens, at most 64. Support files go only in `references/`, `templates/` or `scripts/`. No write follows a link out of the skill's folder.
14. The CLI's own `Skill` tool loading a skill counts as a use and as a read for "patch after read", seen in the chat's stream. Otherwise the curator would archive skills the agent uses natively.
15. Uses count once per run per skill. A use turns a stale skill active again.
16. Undo is offered for every ledger entry, memory ones included. It refuses when the file changed since. Undo of a create archives the skill rather than deleting it. An undo is itself undoable.
17. Gene's edits in the Memory and Skills tabs are ledger entries with source `user`, are not capped, and can be undone. An over-cap file can be shrunk by the agent but not grown.
18. A duplicate memory `add` is a no-op ("Already saved.").
19. Idle means no request to `/api` other than the events stream and the test hooks, and no turn or review running. It is measured by an ASGI middleware with the space's clock. The curator checks every 60 seconds and also skips while "Hide AI features" is on.
20. The consolidation run gets only the three skill tools, a 40-step budget and the agent's default model. Its last text, up to 4,000 characters, is the report. The tool refuses curator changes to pinned or user-made skills, as the prompt asks.
21. Chat search indexes user and assistant text only, not tool results, with snippets marked `«…»`. Reading a chat returns at most 40,000 characters, cut from the oldest messages.
22. `SCHEDULE_SKILLS` is a hook M21 fills; until then no skill counts as used by a schedule. When it raises, the curator leaves that agent's skills alone (fail safe).
23. All strings marked "our string" above, the three review prompts, the consolidation prompt, the learning guidance and the tool-step lines.
