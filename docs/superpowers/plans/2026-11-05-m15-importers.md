# Milestone 15: importers

Expanded 2026-11-05 from the 2026-11-04 features plan, M15 ("Importers"), against `master` at `c72567f`. Built on branch `feat/m15-importers` (built, reviewed and fixed 2026-11-05; results in `m15-acceptance.md`). Everything here is new ("Beyond the catalog") except the Settings section's name and its "Start importing" button, which the behaviour catalog lists under General ("Import Content"); every other label and default is "our string" or "our choice".

**Goal.** Import a Notion Markdown & CSV export, an Obsidian vault or an Anytype Markdown export into a space, with a dry-run preview before anything is written. By default the import makes a new space, so no existing space is at risk.

## What it builds on (read before building)

- **M9's Import CSV** (`frontend/src/types/ImportCsvDialog.tsx`, `frontend/src/lib/csvParse.ts`) maps CSV columns onto an *existing* type's properties and converts each cell with `csvValue` (numbers with `parseNumberInput` and the column's decimal separator from `columnDecimalComma`, booleans from `true`/`yes`/`1`, dates with `parseDateInput`, lists split on commas unless the cell was quoted). **It does not guess kinds.** The kind guessing the 2026-11-04 features plan attributes to it is new work here: `importers/kinds.py` guesses from string cells with the same reading rules as `csvValue` (ported to Python), and for YAML frontmatter values reuses `typedefs._kind_of` and `_inferred_options` (the guessing a space already does for untyped frontmatter).
- **Spaces** (`spaces.py`): `create_space(name, location, 'blank')` makes `<location>/<safe_filename(name)>/.object/space.json` and refuses an existing folder (409). The server serves one space; `POST /api/spaces/switch` restarts it on another folder. The registry is `Registry(state_dir())`. There is no native folder dialog anywhere in the app: "Create new space" and "Open folder…" take a typed path. pywebview is only the window.
- **Writing objects** (`space.py`): `Space.create_object` (frontmatter `id`, `type`, `title`, `createdAt`, `lastUpdated`; body `# <title>`), `safe_filename`, `unique_path` (`` (2)`` on a clash, case-insensitive), `Space._place` (atomic `create_new`, never overwrites, rescans), `Space._apply_values` (API values to frontmatter, as `update_properties` writes them), `Space.create_type` / `save_type` (`typemodel.py`), `unique_key` / `camel_key` (property keys, never reserved), `Space.ensure_tag`.
- **Attachments** (`media.py`): `import_attachment` writes `Attachments/<safe name>.<ext>` (`` (2)``, never overwrites, 100 MiB `MAX_ATTACHMENT_BYTES`). The short-name rule (`findAttachment` in `frontend/src/editor/media/upload.ts`, followed by `export.py`): exact path, then the path ignoring case, then (a bare file name) the first attachment with that file name. An image block is `![name](Attachments/…)` (path percent-escaped as `encodeMarkdownPath` does), any other file `![[Attachments/…]]`.
- **Links** (`resolver.py`, `Space._link_text`): a link is `[[Title]]` unless the title is shared or holds `[`, `]`, `|`, `#` or a line break; then the path form `[[Folder/Stem]]`. Resolution drops `|alias` and `#heading`. An object embed is a line that is exactly `![[Title]]`.
- **Standout quote** (`frontend/src/editor/annotations.ts`): `<!-- block: quote=standout -->` on its own line before a `> ` quote; `color=bg-<theme colour>` also applies to quotes.
- **Search index** (`searchindex.py`): `SearchIndex.reindex()` (`POST /api/search/reindex`); a newly opened space builds its index on start.
- **Settings** (`SettingsModal.tsx`): sections in `SETTINGS_SECTIONS`, ids in `useSettingsModal.ts`.

## Contract (T1)

### Sources and detection

A source is a **`.zip` file or a folder**, named by its absolute path on this device. `POST /api/import/preview` takes `{source: {path, kind}}` with `kind` `auto` (default), `notion`, `obsidian` or `anytype`. Detection (`auto`), in order:

1. **Obsidian:** a `.obsidian/` folder at the root (or under the zip's single top folder).
2. **Notion:** at least half of the `.md` and `.csv` files have a stem ending in a space and 32 hex digits (`Page 0123…cdef`), or a dashed UUID (our choice to accept both).
3. **Anytype:** a marker only its export has. The export's exact layout is not documented on its help page (it lists Markdown, "Include linked Objects", "Include files", "Include archived Objects"; its 0.47.4 release notes say Markdown export "now includes properties and types", as frontmatter). **Lane B fixes the marker and the type key from a small real export Gene makes** (synthetic fixture after it); until then `auto` never answers `anytype` and the user picks it.
4. Anything else with Markdown files: read with the Obsidian rules (a plain Markdown folder), `detected: null`, and the preview warns (our string: "Couldn't tell where this export came from; it is read as a Markdown folder.").

A chosen `kind` always wins over detection; `detected` reports what detection found.

### How the source reaches the server (our choice)

**By path, read in place.** The dialog has a path field (as "Create new space" > Location and "Open folder…" do); the server, which runs on this device, reads the zip or folder directly. No upload, no copy, no extraction to disk: a zip is read entry by entry with `zipfile`, a folder with `os.walk`. Rationale: exports can be several GB; the app has no native file dialog, and a file input in the webview gives bytes but no path. Drag-and-drop and a native picker are later.

**Safety and limits** (`importers/source.py`; every limit our choice):

- **Nothing in the source is ever written, renamed, moved or deleted.** No temporary extraction anywhere.
- **Entry names are never write paths.** Every file the import writes gets a name computed from a title (`safe_filename` + `unique_path`) or an attachment name (`media._safe_attachment_name` rules) under the target space. Source names are used only to match links.
- **Zip-slip / traversal:** an entry is normalised (`\` to `/`, a leading `./` dropped); one that is absolute, has a drive letter, a `..` component, a NUL or a name that can't be decoded is skipped (`unsafePath`) and never read. In a folder, every file's real path must be inside the source's real path.
- **Symlinks ignored:** `os.walk(followlinks=False)`, files that are links or junctions skipped (`symlink`); zip entries whose mode marks a link skipped.
- **Encrypted entries** skipped (`encrypted`).
- **Nested zips:** zip files at the top level of the source (Notion's multi-part export, `Export-…-Part-1.zip`) are read as part of it, one level only; deeper ones are skipped (`nestedArchive`). A zip inside the source zip is read into memory up to 256 MiB (our choice); a larger one deflated in the outer zip is read through checkpoints of the inflater's state, so reading its entries in any order never inflates it again from the start (review fix, 2026-11-05). Nothing is extracted to disk.
- **Limits:** at most 100,000 entries and 50,000 objects (413 above); a Markdown or CSV file over 20 MiB is skipped (`tooLarge`); an attachment over 100 MiB (`MAX_ATTACHMENT_BYTES`) is skipped; the preview reads at most 512 MiB of Markdown and CSV text in all (413 above). Attachment bytes are never read by the preview, only sizes. A zip entry that yields more bytes than its header says is cut off and skipped (`damaged`): zip bombs stop at the declared size.
- **Dot-folders** are not entered (`.obsidian/` is read for detection only and listed once as `appSettings`; `.trash/` skipped).
- **Text:** read with `textfile.decode` (BOM and CRLF understood); bytes that aren't UTF-8 are replaced and the file is listed (`notUtf8`). New files are written with LF and no BOM, as `create_object` writes them.
- **Fingerprint:** for a zip, its size and mtime plus every entry's name, size and CRC; for a folder, every file's relative path, size and mtime. `start` answers 409 when it no longer matches the preview's.

### The in-memory model (`importers/model.py`, T1)

`ImportPlan` (dataclasses, never serialised): `kind`, `sourcePath`, `container`, `fingerprint`, `suggestedName`, `types: PlanType[]`, `objects: PlanObject[]`, `attachments: {sourcePath: PlanAttachment}`, `skipped: SkippedItem[]`, `warnings`, `frontmatterKeys`, `folders`.

- `PlanType {key, name, pluralName, origin: database|folder|key|page, originLabel, properties: PlanProperty[], existingTypeId, skip}`. Keys: `database:<csv path>`, `folder:<name>`, `key:<value>`, `page`.
- `PlanProperty {key, sourceName, name, kind, guessedKind, isArray, systemKey, options, skip}`; `kind` is one of `text`, `number`, `boolean`, `url`, `datetime`, `label`, `entity` (`ImportKind`); `systemKey` (`title`, `tags`, `aliases`, `description`, `createdAt`, `lastUpdated`) marks a field that fills the app's own field.
- `PlanObject {sourcePath, title, typeKey, values (raw source values per property key), system, links: PlanLink[], attachments, targetPath, renamedFrom, mtime}`.
- `PlanLink {sourcePath, raw, target, kind: object|attachment|database|external|unresolved, text, heading, embed}`.
- `PlanAttachment {sourcePath, size, targetName}`.
- **Bodies are not kept** (our choice, memory): the preview parses each file for links and attachments and drops the text; the writer reads each file again (after the fingerprint check) and converts it with the plan's link table. Conversion is deterministic, so the preview's counts are what gets written.

The planner (shared, after the reader) applies the mapping, picks property keys, plans each object's `targetPath` and each attachment's `targetName` against the target (an empty folder for a new space; the open space's files for `currentSpace`), and resolves links.

### Preview API

`POST /api/import/preview` `PreviewRequest {source: {path, kind}, mapping?, target?: 'newSpace' | 'currentSpace'}` -> `ImportPreview`. Synchronous (our choice: it reads text only, within the limits above); writes nothing anywhere, not even in the state dir. `404` no such file or folder, `415` neither a zip nor a folder (or a zip that can't be opened), `413` over the limits, `422` a mapping that names an unknown type key, property key or existing type.

Sent again with a `mapping`, it re-plans; when the path, kind and fingerprint are unchanged the server reuses the read (the last 3 reads are kept, least recently used dropped first, each for 30 minutes; a read is dropped when an import starts from one of its previews; our choice, review fix 2026-11-05). `start` with an unknown or expired `previewId` answers `404` and the dialog previews again.

`ImportPreview` (mirrored in `frontend/src/api/types.ts`): `previewId`, `sourcePath`, `kind`, `detected`, `container`, `suggestedName` (the zip's or folder's name; Notion's `Export-<uuid>` names become "Notion import", our string), `counts {objects, types, properties, attachments, attachmentBytes, links, resolvedLinks, unresolvedLinks, renamed, skipped}`, `types: PlannedType[]` (each with `objectCount` and `properties: PlannedProperty[]` carrying `guessedKind`, `valueCount`, `unconvertible`, up to 3 `samples` and up to 50 label `options`), `mapping` (the effective one, defaults filled in), `frontmatterKeys` and `folders` (`[name, count]` pairs, Obsidian/Anytype), `samples` (the first 20 planned objects with their target paths), `skipped` (the first 500; `counts.skipped` has the total), `warnings`.

### Mapping step

`ImportMapping {typeSource, typeKey, types, properties}`:

- **Notion:** each database CSV is a type; pages outside every database are `Page`. `typeSource` is ignored.
- **Obsidian and Anytype:** `typeSource` `folder` (Obsidian default): each **top-level** folder holding Markdown is a type (subfolders belong to their top-level folder's type, our choice); `key`: the value of frontmatter key `typeKey` (Anytype default, with the export's own type key) is the type; `none`: everything is a `Page`. Files at the root, and files without the key, are `Page`. A folder holding no Markdown (an attachments folder) never makes a type.
- **Type names (our choice):** a database's name is its CSV stem (id stripped); a folder's type name is the folder name made singular by a plain English rule on its last word (`ies` -> `y` but `Movies` -> `Movie`; `sses`, `xes`, `ches`, `shes` drop `es`; a final `s` dropped unless `ss`, `us` or `is`; `Series`, `Status`, `News` and a few others unchanged; never empty), its plural the folder name; a key value is the name and `<name>s` the plural. All are editable (`types[key].name`, `.pluralName`).
- `types[key].skip`: leave those objects out (listed as `userSkipped`).
- `types[key].existingTypeId` (only with the `currentSpace` target): put the objects into that existing type. Default: the existing type whose name matches case-insensitively (our choice), else a new type. Types whose objects aren't pages never match and answer `422` (naming the type) when chosen: read-only types and every basic type but Page and Task (Tag, DailyNote, Whiteboard, the media types Weblink, File, Image, PDF, Audio, Video, Tweet); custom types and the basic Page and Task always can (`planner.importable_type`, the same rule as the dialog's "Add to" list; review fix 2026-11-05).
- `properties[typeKey][propKey]`: `kind` (any `ImportKind`), `isArray` (for `label` and `entity`), `name`, `skip`. The preview answers the guessed kind and how many values won't fit the chosen one (`unconvertible`); those values are dropped and listed (`valueNotConverted`). A property mapped onto an existing type's property of the same key keeps the existing kind (it's never changed); values that don't fit it are dropped and listed.

**Kind guessing** (`importers/kinds.py`; our choice, every guess overridable): typed YAML values go through `typedefs._kind_of` (lists of `[[links]]` -> `entity`, lists -> `label`, booleans, numbers, `[[link]]` -> `entity`, URLs -> `url`, dates -> `datetime`, a repeated value or a key such as `status` -> `label`, else `text`). String cells (Notion CSV): all `Yes`/`No` -> `boolean`; all numbers (decimal separator per column as `columnDecimalComma`; a trailing `%` or a leading `$ € £ ¥` allowed) -> `number`; all ISO dates or Notion dates (`November 5, 2026`, with a time `3:00 PM`, ranges with `→`) -> `datetime`; all URLs -> `url`; all relation cells (`Title (Path%20<id>.md)` items) -> `entity` list; cells with comma-separated parts that repeat across rows (at most 50 distinct parts, none over 40 characters) -> `label` list; a column of at most 50 distinct values with repeats -> single `label`; else `text`. Empty cells don't count.

**System fields (our choice):** `title` from the page title (Notion: the CSV's title column, else the page's `# heading`, else the file stem; Obsidian/Anytype: frontmatter `title`, else the file stem). `tags` from frontmatter `tags`/`tag` (lists or comma strings, a leading `#` dropped) plus Obsidian inline `#tags` outside code (the inline text stays as written); one Tag object per distinct tag, made or reused as `Space.ensure_tag` does. `aliases` from `aliases`/`alias`. `description` from `description`. Notion's "Created time" / "Last edited time" columns fill `createdAt` / `lastUpdated`; otherwise both are the source file's modification time (a zip entry's date), and the import time for a CSV row with no page. Keys a source app uses only for display (Obsidian `cssclasses`, `cssclass`, `publish`, `permalink`) are dropped and listed (`appSettings`). A source key that is reserved in Object (`SYSTEM_KEYS`, e.g. `date`, `url`, `source`) but isn't one of the fields above keeps its name and gets a free key (`unique_key`: `date_`). Keys are kept as written when free (Obsidian/Anytype, so files stay readable to the source app's conventions), else `unique_key(name)`; Notion column keys are `unique_key(header)`. Nested maps and lists of maps are written as they are under their key and don't become properties (listed in the preview's warnings, our choice).

### Import API

`POST /api/import/start` `StartImportRequest {previewId, mapping, target}` (a `clientId` is accepted and ignored: the job announces one resync with no origin when it ends) -> `202 {jobId, targetPath}`.

- **`target: {kind: 'newSpace', name, location}`** (default in the dialog; name defaults to `suggestedName`, location to the current space's parent folder). Checked before the job starts: `422` bad name, `404` location not a folder, `409` the folder exists (as `POST /api/spaces`). The job calls `create_space(name, location, 'blank')`, opens a second, unserved `Space` on it (no watcher, no search index) and writes through it. When the job ends with anything written, the folder is registered (`Registry.register(path, touch=False)`); the dialog then offers "Switch space" (the new space builds its index when it opens).
- **`target: {kind: 'currentSpace'}`** — **allowed in v1 only when the user explicitly picks "This space"** (our choice). It writes through `ctx.space` (so the in-memory scan, resolver and history stay right). Nothing is announced per object or type; when the job ends having written anything (done, stopped or failed), it calls `ctx.search.reindex()` and announces one resync, the watcher's (`types` at path `*`, no origin), so every window, the importing one included, reloads once (review fix 2026-11-05).
- `422` when a new space would be inside the source folder, or the source is inside the target space (importing a space into itself). `409` the source's fingerprint changed (re-preview), or another import is running (one at a time, our choice). `404` unknown or expired `previewId`.

`GET /api/import/jobs/{id}` -> `ImportJob {id, phase, done, total, targetPath, currentPath, result, error}`; `phase` runs `preparing`, `types`, `attachments`, `objects`, `report`, then `done`, `failed` or `cancelled`. `POST /api/import/jobs/{id}/cancel` -> `{ok}`: stops after the file being written. Jobs live in memory (a server restart forgets them; the dialog never switches space while one runs).

**Progress (our choice):** the dialog polls the job every 500 ms and shows "Importing… `done` / `total`" with the current file; `total` is attachments + objects + 1 (the report).

**Failure and cancel:** nothing written is removed (the import only ever adds files; removing them would need the trash). The Import report is still written, saying the import stopped and what was written (and, when it stopped early, that links to objects not written stay unresolved). The job re-opens the source and checks its fingerprint before it makes the new space, so a source gone meanwhile fails the job with nothing created. A single file that can't be written (a name the file system refuses, permissions) is skipped and listed (`damaged`, "Couldn't be written: …"); the import goes on. `ImportResult {targetPath, spaceName, objects, types, attachments, tags, skipped, reportPath, cancelled}`.

### Conflict rules

- **Existing files are never overwritten**: every object and attachment is a new file through `create_new` (`Space._place`, `import_attachment`'s loop). A name already taken gets `` (2)``, `` (3)``… (case-insensitive).
- **Duplicate titles** (within the import, or against the open space's objects for `currentSpace`): the title stays, the file gets `` (2)`` (as `create_object` does), and links to it use the path form (`[[Folder/Title (2)]]`) as `_link_text` would. Counted in `counts.renamed` and listed in the report. Notion's many "Untitled" pages fall here.
- **Types:** a new type whose name is taken gets `` (2)`` in the name (our choice); a new type whose folder (its plural's file name) is taken by another type, ignoring case, gets `` (2)`` in the plural, so no two types share a folder that is one folder on Windows. An existing type (only via `existingTypeId`) gains the missing properties through `save_type`; its existing properties, kinds and options are never changed or removed (label options are added).
- **Tags:** an existing Tag object (case-insensitive) is reused.

### Per-source rules

**Notion (Markdown & CSV export)**

- **Id suffixes:** a trailing space plus 32 hex digits (or a dashed UUID) is stripped from every file and folder stem used as a title, type name or link match. The ids stay in the plan for matching only.
- **Pages:** each `.md` is an object. Its first `# Title` line is the title and stays as the body's heading (Object's own convention). Pages in no database are `Page` objects.
- **Databases:** `Name <id>.csv` is a type named `Name`; when both `Name <id>.csv` and `Name <id>_all.csv` exist, `_all` is read (it has every row) and the other ignored. Each row is an object; the CSV's first column is the title. Rows are matched to page files in the folder `Name <id>/` by stripped title, in order for equal titles (our choice). A row page's leading `Key: value` lines (Notion writes the row's properties under the heading) are removed from the body when the key is a column of the CSV; the CSV's values are the ones used. A row with no page is an object with an empty body (`# Title` only). A page in the database folder with no row is still an object of the type, its `Key: value` lines read as values.
- **Relations:** `Title (Path%20<id>.md)` items in a cell -> `entity` values `[[Title]]` (or the path form) of the matched objects; an item whose page isn't in the export keeps its text as an unresolved link (listed). People, created-by and formula/rollup values are their exported text (Object has no formula kind yet, M12).
- **Links:** `[text](Relative%20Path%20<id>.md)` (decoded, relative to the page) -> `[[Title]]`, or `[[Title|text]]` when the text differs from the title (our choice). A link to a `.csv` (a database) becomes its text (`databaseLink`, listed). A link to a page not in the export becomes its text (`unresolvedLink`). Web links stay.
- **Images and files:** `![alt](Page%20<id>/image.png)` -> the file copied to `Attachments/` and `![alt](Attachments/image.png)`; a link to another local file -> copied, and `![[Attachments/file.pdf]]` when it is alone on its line, else `[text](Attachments/file.pdf)` (our choice). Missing files: the link text stays, listed (`missingAttachment`).
- **Callouts:** an `<aside>` block -> a standout quote: `<!-- block: quote=standout -->` then the content as `> ` lines, the leading emoji kept as text (our choice: no colour; the export has none).
- **Other HTML** Notion writes (`<details>`/`<summary>` toggles, tables it couldn't write as Markdown) stays as written in v1 (our choice), listed once in the warnings.

**Obsidian vault**

- Frontmatter maps almost directly (system fields above; other keys are properties of the object's type).
- **Wikilinks:** `[[Note]]`, `[[Note|alias]]`, `[[Note#Heading]]`, `[[Note#^block]]`, `[[folder/Note]]` resolve as Obsidian does (exact path, else the file name anywhere, shortest path first) and are rewritten to the target's link text, keeping `#…` and `|alias` (`[[Title#Heading|alias]]`). Unresolved ones stay as written (Object shows them as missing; listed). Markdown links to `.md` files are handled like Notion's links.
- **Embeds:** `![[Note]]` -> `![[Title]]` (an object embed when alone on its line); `![[image.png]]` and `![[image.png|300]]` -> `![](Attachments/image.png)` with `<!-- block: width=300 -->` before it when alone on its line; `![[file.pdf]]` -> `![[Attachments/file.pdf]]`. Attachments are found by Obsidian's short-name rule (the same rule as `findAttachment`): the exact path, the path ignoring case, then the first file with that name (shortest path first).
- **Callouts:** `> [!type] Title` (and `[!type]-`/`+` folds) -> a standout quote; the marker is dropped and the title kept as the first line in bold (our choice).
- Folders and frontmatter keys map to types in the mapping step (above).

**Anytype Markdown export**

- Each `.md` is an object; its frontmatter properties become properties (kinds guessed as for Obsidian); the type comes from the export's type key (`typeSource: 'key'` by default). Links and files: relative Markdown links to `.md` files and to files in the export are handled as for Notion (without id suffixes). Lane B pins the exact frontmatter shape, type key and files folder from Gene's sample export and writes the synthetic fixture after it.
- **Lane B note (unverified):** no real Anytype export was available, so the reader is best effort and unverified against one. It reads Markdown files with YAML frontmatter, keys becoming properties; the type key is assumed to be `type` (missing → `Page`); files in the export are handled as relative links like any other. There is no marker: `auto` never answers `anytype` (the user picks it), and the preview's warnings and the Import report say the reader is unverified. Pin the marker, type key and files folder once a real export is at hand.

### Import report

One `Page` object titled **"Import report"** (our string; `` (2)`` when taken), written last into the target space's Page folder. Body (our strings): the source path, kind and time; counts (objects, types, attachments, tags); sections "Skipped" (every skipped item: source path, reason, detail), "Renamed" (duplicate titles and their files), "Unresolved links", "Values not converted" (type, property, object, value). Each section is a Markdown list, capped at 5,000 lines with "…and N more" (our choice). Links in it are `[[…]]` to the imported objects where one exists. It is an ordinary object (the user can delete it).

### What is written, and what is never touched

- **New space:** `.object/space.json` (via `create_space`), `.object/types/<id>.json` per type (`Page` included when used, our choice: `Page`/`Pages`, folder `Pages`), the objects in their types' folders, `Attachments/…`, `Tags/…` Tag objects, the Import report. The registry entry in the state dir. Nothing else in the state dir.
- **Current space (when picked):** new type files, added properties on mapped existing types (`save_type`), new object files, new attachments, new Tag objects, the report. No existing object file is opened for writing; version history isn't involved (it runs only before replacing a file).
- **Never touched:** the source (zip or folder) and anything beside it; any other space; `C:\Git\wiki` (never referenced); files outside the target space.
- **Objects:** frontmatter `id` (new ULID), `type`, `title`, the mapped properties in source order (encoded as `_apply_values` encodes them, so files look like the app wrote them), `tags`, `aliases`, `description`, `createdAt`, `lastUpdated`. Templates are not applied (`templateId: 'none'`, as Import CSV).

### Not in v1

Daily-note detection (Obsidian daily notes folders become an ordinary type), Notion inline databases' views, Notion comments, Obsidian Canvas (`.canvas`, skipped as `unsupported`), Anytype's other formats (Any-Block, JSON/Protobuf), a native file picker or upload, other sources (the catalog's Evernote, Apple Notes and Tana guides).

## Review focus

The source is never written and no entry name ever becomes a write path (zip-slip, `..`, absolute and drive paths, symlinks, nested zips, oversize entries); nothing is written on preview, not even in the state dir; existing files are never overwritten and existing types never lose or change a property; a cancelled or failed import leaves only whole new files plus a report; every skipped or dropped item reaches the report; links resolve to the right object when titles repeat; a 5,000-page synthetic export previews in seconds and imports with steady progress; the current-space path keeps the scan, resolver and search index right (and unlinked mentions still work on imported objects).

## Our choices (settled here)

1. Source by typed absolute path, read in place; no upload, extraction or native picker in v1.
2. Limits: 100,000 entries, 50,000 objects, 512 MiB of text per preview (413), 20 MiB per Markdown/CSV file and 100 MiB per attachment (skipped), zip entries cut at their declared size.
3. Top-level zips in the source read (Notion's multi-part export), one level only.
4. Detection order Obsidian, Notion, Anytype (marker from Gene's sample), else a Markdown folder read with Obsidian rules.
5. Preview synchronous and write-free; the latest read cached 30 minutes for re-planning; import runs as a job polled every 500 ms; one import at a time.
6. Bodies not kept in the plan; the writer re-reads after a fingerprint check.
7. New space by default; the open space allowed when explicitly picked; no other existing space.
8. Types: Notion database = type; Obsidian top-level folder = type (subfolders inherit); Anytype by type key; everything else `Page` (a stored `Page`/`Pages` type made when needed). Folder type names made singular by a plain English rule; all editable.
9. With the open space as target, a planned type maps to the existing type of the same name by default; existing types only gain properties and label options.
10. Duplicate titles keep their title, get `` (2)`` in the file name and path-form links; a taken type name gets `` (2)``.
11. Kind guessing as listed under "Mapping step"; values that don't fit the chosen kind are dropped and reported.
12. Obsidian keys kept as written when free; Notion keys `unique_key(header)`; reserved keys get `unique_key`.
13. `createdAt`/`lastUpdated` from Notion's created/edited columns, else the file's modification time.
14. Inline `#tags` also become `tags`; Tag objects made or reused; display-only keys dropped and reported.
15. Notion row matching by stripped title in file order; `_all.csv` preferred; the row page's property lines removed from its body.
16. Links with different text become `[[Title|text]]`; links to databases or to pages outside the export become plain text.
17. Callouts (`<aside>`, `> [!type]`) become standout quotes (`<!-- block: quote=standout -->`), emoji and title kept; other HTML kept as written.
18. Images `![](Attachments/…)` (width from `|N` as `<!-- block: width=N -->`); other files `![[Attachments/…]]` alone on a line, else an inline link.
19. New files LF without BOM; no template applied.
20. Failure or cancel removes nothing; the report is still written. The report is a `Page` "Import report", lists capped at 5,000 lines.
21. Fixtures are synthetic folders zipped at test time.
