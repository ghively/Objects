## Findings, most severe first

Severity: HIGH = data loss, corruption, security, or a crash on a common path; MEDIUM = wrong behaviour on a
realistic path; LOW = edge case; POLISH = copy, label, order, consistency against the catalog.

### HIGH

1. **The sensitive-content scan skips every file inside a Notion multi-part export** (and any zip at the top
   level of a folder source), which the import then reads and hands to the filing agent. CONFIRMED (R).
   `backend/objectapp/importscan.py:274` counts a `.zip` member as unscanned and the folder walk never opens one,
   while `importers/source.py:399,601` (`_nested_zip`) reads a top-level zip one level deep, and
   `importers/agentwire.py:64-68` marks only *flagged* files `excludeFromAI`. An export holding
   `Export-…-Part-1.zip` with a page `prod db password = …` scans as `scanned 0, unscanned 1, flagged 0`, the
   wizard shows "0 files scanned, 0 flagged, 0 left out.", and the import writes the page with the secret and
   no `excludeFromAI`. Fix: scan a top-level `.zip` member (and a top-level `*.zip` file in a folder) one level
   deep with the same caps, so the scan and the lister read the same set.

### MEDIUM

2. **The `structure` to `type` compatibility layer renames a user's own property keys on every write.**
   CONFIRMED (R). `keycompat.py:33-83` (`OLD_KEYS`, `upgrade_keys` walks every dict at every depth),
   `:118-158` (`KeyCompatMiddleware` on every `/api` and `/api/v1` JSON POST/PUT/PATCH), `api_v1_tools.py:289`
   (the in-process MCP calls). Property keys come from names (`camelCase`), so a property named "Structures"
   (key `structures`, a list) or "Structure ID" (`structureId`, a string) is written under `types:` / `typeId:`
   by `PUT /api/object/properties`, object creation, `POST /v1/object/properties` and `set_properties`; the real
   property keeps its old value and a stray key appears. Also (LOW) a body with an old key and a lone surrogate
   makes `upgrade_body` raise `UnicodeEncodeError` (a bare 500, `keycompat.py:104`). Fix: never descend into
   value subtrees (`updates`, `values`, `set`, `add`, `remove`, `mapping`, …); catch the encode error.

3. **Editing a paragraph that holds `[[Page#Heading]]` or `[[Page#^id]]` saves `[[PageHeading]]` /
   `[[Page^id]]`.** CONFIRMED (R). `frontend/src/editor/extensions/wikilink.ts:9-33`: the tokenizer accepts `#`
   in a target but the serializer sends every target through `wikilinkTarget`, written for titles, which strips
   `[`, `]` and `#`. One typed character anywhere in the paragraph breaks the link (the chip dims, the backlink
   disappears, the anchor or block id is gone). The backend treats both forms as links (`resolver.py:52-64`,
   `relink.py:32`, `linkindex.py:10`). Fix: strip only what the tokenizer cannot hold (`[`, `]`, `|`, newline).

4. **A read-only Work run or an import-filing run can delegate and get a full-write run.** CONFIRMED (R).
   `api_agent_a2a_v1.py:106-110` (`flat()` checks `token.scope` only); the purpose-based `WRITE_GUARDS`
   (`worktools.read_only_write_guard`, `importfiling.filing_write_guard`) run on every other v1 write route but
   not on `delegate` and `remote-call`. A `work-read` token gets 403 on `POST /v1/objects` and 200 `completed`
   on `/v1/agent/delegate`; the delegated CLI run has every write tool. Only the CLI's `--disallowedTools` list
